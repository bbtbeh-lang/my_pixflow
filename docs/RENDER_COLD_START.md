# دستورالعمل: حل مشکل Cold Start در هاست رایگان Render

این دستورالعمل رو برای هر سایت جدیدی که روی **Render (Free Tier)** دیپلوی می‌کنی اجرا کن. برای تمام سایت‌های Pixflow (فعلی و مشتری‌های آینده) قابل استفاده‌ست.

---

## مشکل چیه؟

Render تو تیر رایگان، بعد از **حدود ۱۵ دقیقه بدون ترافیک** سرور رو "می‌خوابونه" (spin-down). اولین کاربری که بعد از این خواب به سایت سر بزنه، باید صبر کنه (معمولاً ۳۰-۶۰ ثانیه) تا سرور دوباره بیدار بشه. این تجربه‌ی بدی برای بازدیدکننده یا مشتریه.

**نکته مهم:** این cold start فقط تأخیره، نه از دست رفتن دیتا — چون دیتابیس (Supabase) جدا از سروره و همیشه در دسترسه.

---

## راه‌حل: نگه‌داشتن سرور بیدار با Health Check + Uptime Monitor

### مرحله ۱ — اضافه‌کردن اندپوینت `/health` به بک‌اند

توی `server.js` (یا معادلش) این route رو اضافه کن — **قبل از** static file serving:

```js
// Lightweight endpoint for uptime monitors to ping and prevent
// the free-tier host from sleeping. عمداً به دیتابیس دست نمی‌زنه.
app.get('/health', (req, res) => {
  res.status(200).json({ status: 'ok', uptime: process.uptime() });
});
```

قوانین مهم برای این endpoint:
- هیچ‌وقت به دیتابیس read/write نکنه (نه ریسک، نه هزینه‌ی اضافه روی Supabase)
- هیچ auth نمی‌خواد — باید عمومی و سبک باشه
- فقط باید سریع جواب ۲۰۰ بده

### مرحله ۲ — ست‌کردن یه Uptime Monitor رایگان

یکی از این سرویس‌ها رو استفاده کن (هر دو رایگانن):
- **UptimeRobot** (uptimerobot.com)
- **cron-job.org**

تنظیمات:
1. یه مانیتور جدید بساز
2. آدرس: `https://<domain-سایت>/health`
3. فاصله‌ی زمانی: **هر ۱۰ تا ۱۴ دقیقه** (باید کمتر از ۱۵ دقیقه‌ی خواب Render باشه)
4. نوع چک: HTTP GET، انتظار status code 200

### مرحله ۳ — تست نهایی

- آدرس `/health` رو تو مرورگر باز کن — باید فوری JSON برگردونه
- چند دقیقه صبر کن و دوباره لود کن — عدد `uptime` باید مدام بالا بره، نه صفر بشه (یعنی سرور نخوابیده)
- تو داشبورد UptimeRobot/cron-job.org چک کن که پینگ‌ها همه سبز (موفق) باشن

---

## چک‌لیست برای هر پروژه‌ی جدید

- [ ] endpoint `/health` توی سرور اضافه شده
- [ ] endpoint هیچ ارتباطی با دیتابیس نداره
- [ ] یه مانیتور UptimeRobot یا cron-job.org روی دامنه‌ی سایت فعال شده
- [ ] فاصله‌ی پینگ زیر ۱۵ دقیقه‌ست
- [ ] تست شده که uptime واقعاً صفر نمی‌شه

---

## نکته‌ی جانبی — کِی این راه‌حل کافی نیست

اگه سایت مشتری ترافیک جدی داره یا نمی‌خوای اصلاً ریسک تأخیر رو داشته باشی، تیر پولی Render (Starter, ~$7/ماه) دیگه اصلاً spin-down نداره. این dastورالعمل مخصوص وقتیه که می‌خوای هزینه‌ی هاستینگ رو صفر نگه داری (مثلاً برای مشتری‌های تازه یا پکیج پایه).
